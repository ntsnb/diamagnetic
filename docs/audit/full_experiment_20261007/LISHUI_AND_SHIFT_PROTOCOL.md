## 时间、真值与输入契约

小时 t 定义为原生样本时刻落在 **(t−1 小时, t]** 的观测平均值，右闭区间、右端时间标签。这一统计量在 t 才可用。15 分钟来源每小时必须有全部 4 个有效原生位置；5 分钟来源必须有全部 12 个。覆盖不足时，`load=NaN`、`load_observed=0`，实际覆盖数和比例另行保留。最后一个输出小时不会晚于原生文件实际观测终点。

该定义是“过去一小时已观察样本的均值”。源文件没有提供传感器采样点代表瞬时值还是此前间隔平均的说明；本次没有把它擅自解释为能量。

- `source_load`：原生文件的数值，包含被判为无效的负值；原文件不动。
- `source_row_present`：区分原文件存在此行与缺失时间位置。
- `load`：有效目标；非有限数与负值按显式规则掩码，零值保留。没有全段 IQR 筛选、目标插值或反向填充。
- `load_input`：只用此前有效小时负荷前向填充的输入；第一个有效值之前仍为 NaN。
- `load_observed`：目标真值是否有效；不得作为待预测数值或填补标签。
- `load_input_observed`：当前输入是否来自当前已观测值的质量标记。
- 输入还包含小时、星期、月份的正余弦特征；不添加不可追溯气象数据。

模型读取契约：`target_columns=["load"]`、`target_input_columns={"load":"load_input"}`、`target_mask_columns=["load_observed"]`。`feature_columns` 显式列出 `load_input,load_input_observed,hour_sin,hour_cos,dow_sin,dow_cos,month_sin,month_cos`。覆盖数和标签掩码不会因自动数值列选择而进入输入。

发行 t 的输入只含 t 及此前观测，目标为 t+1…t+H；完整标签释放时刻是 **t+H+extra_delay**。`chronological_issue_indices` 按目标行切分，要求每个完整目标窗口都落在本段内，上一段历史可作为下一段输入。末尾释放时刻可以超出数据终点，索引仍保留，运行器不能因此读入未来真值。不完整监督目标窗口应跳过参数更新；评分应按原始目标掩码计有效项，不能前向填充目标以“补齐”评分。

## 旧 shifted-stream 的实际规则

证据：`train/run_shifted_sota_methods.py:292` 默认加载 `configs/tuning/load_candidate_i_shifted.yaml`；旧丽水入口 `train/run_lishui_shifted_sota.py:84` 强制 `chronological_shifted`、20% 测试块与 35% 候选池。真正选段在 `data/loaders.py:12–56,75–111`，不是入口脚本中的检测器。

先使用 `data/windowing.py` 构造 N=T−L−H+1 个重叠窗口。旧划分按 **窗口数 N** 计算 `n_train=floor(.55N)`、`n_val=floor(.10N)`。`n_test=min(N−n_train−n_val,max(1,floor(.20N)))`。`pool_size=max(n_test,floor(.35N))`，`pool_start=max(n_train+n_val,N−pool_size)`，`pool_end=N`。候选起点为 `pool_start` 至 `N−n_test` 的每一个整数，均包括端点；每个候选都是长度 n_test 的连续输入窗口块。

把每个输入窗口 x 展平为 L×F 个坐标。训练输入统计量为 μ_tr、σ_tr、v_tr，候选输入为 μ_c、v_c；方差使用总体方差（ddof=0）。旧分数：

```text
score = mean_j(|mu_c[j] - mu_tr[j]| / max(sigma_tr[j], 1e-6))
      + 0.1 * mean_j(|log(max(v_c[j], 1e-6)) - log(max(v_tr[j], 1e-6))|)
```

选择 score 最大的候选；旧 `if score > best_score` 保留首个严格并列最大。用的是 **x 输入窗口，不直接读取 y 预测目标数组**；但 x 本身包含负荷历史、气象等全部输入，而且选段时提前查看了全部未来候选块。故存在未来输入可见性和事后选择偏差，不能称为“不知道未来”的在线漂移检测，也不能把该段结果泛化为整个实际在线后缀的性能。

旧的其他语义不能被新版默认继承：

- 旧 `data/lishui_dataset.py:100–117,161–162` 对负荷做全数据 IQR 过滤、小时平均、双向时间插值和前后填充；零也被当缺失。气象也双向插补，原缺失真值掩码不可恢复。
- 旧小时平均默认左端标签，使标为 t 的小时平均可能包含 t 之后的原始时刻；新数据明确改为右端可用时间。
- 旧 `train/run_experiment.py:156–158` 在前 floor(.55T) 原始行上做 float32 标准化，再在窗口层切分，不是新版目标行边界。
- 旧窗口切分可能使相邻段的目标覆盖重叠 H−1 个时刻；新版严格目标范围不会这样切。
- 旧 `train/run_shifted_sota_methods.py:38–39` 使用 `drop_last=True`，batch_size=64 时实际消费窗口数是 floor(n_test/64)×64，冻结文件同时记录名义长度与旧实际消费长度。
- 旧输入选段规则与旧 `LabelBuffer` 的样本/标签对齐是否正确是两件事；复现选段不能证明旧反馈实现有正确的 t+H+delay 时序。

## 可复用选段 API 与冻结证据

`paper_impl/stream_protocols.py` 提供：

- `select_stream_indices(..., protocol="chronological")`：不看数值，使用全部剩余后缀；可只传样本数。不要为它传入20%块后误称全后缀。
- `select_stream_indices(x, protocol="legacy_shifted")`：复现旧窗口计数、每个候选位置及分数公式，显式记录 `future_inputs_for_selection=true`，返回训练/验证/测试索引和完整候选分数。
- `chronological_issue_indices(...)`：按原始目标行严格划分并生成 t 与 t+H+delay。
- `write_selection_manifest(...)`：保存索引、参数及内容哈希。同一路径允许相同内容幂等重写，不允许不同内容覆盖冻结结果。

旧规则实现用 float64 中心化累积矩加速，公式等价，**不是原 torch float32 的逐位复现**。21 项测试中的真实旧函数对照验证候选、选中索引和分数；另对九个实际旧清洗数据核对所选点与相邻 ±2 个点的旧 `_shift_score`，局部最优起点均一致，最大分数绝对差 2.73×10⁻⁸。没有声称已经用旧慢循环逐一重算所有实际候选。

旧九县的冻结文件在 `data/lishui_online/legacy_shifted_v1/lishui_*.json`。它们保存原已清洗文件哈希、全部输入特征、旧 scaler 拟合行数、候选起点与分数、选中索引、drop_last 数量和插补真值警告。示例：云和 [8993,11759)，莲都 [8528,11134)，遂昌 [9005,11772)；这些是旧输入窗口索引，不能当作新 v2 的原始时间行索引。
